## Part 2: Design

### 1. What overall style will best represent you (minimalist, creative, professional, etc.)?

A simple professional style with straight forward readable text, a personal photograph, and organized sections.

### 2. What color scheme will you use and why?

Dark navy, teal, white, and pale green. Navy gives the text strong contrast, teal highlights actions, and pale backgrounds separate sections.

### 3. What fonts will you use for headings and body text?

Arial with a sans-serif fallback for headings and body text. Larger and bolder headings create a clear hierarchy and gives the main idea of my project.

### 4. How will your design reflect your personality or field?

The organized layout reflects my interest in information systems and databases. My photograph makes the introduction personal, and the project cards show my technical interests.

### 5. What layout will your homepage follow?

Header and navigation, introduction and photograph, About, Skills, Projects, and Contact.

### 6. How will you organize project sections visually?

Each project uses a bordered card with a title, description, and technology or coursework tag. The Academic Planning card includes a mockup of what it is. The Anime track Subscription card retains an AniTrack menu image of what every user sees. Filter buttons appear above the projects as well.

### 7. Will the site be mobile-friendly? How will you ensure responsiveness?

Yes. I used Flexbox to arrange the content and allow rows to wrap. At screen widths of 700px or less, a media query stacks the main sections vertically. Images resize with their containers. I will check the website on a phone to make sure everything fits.

### 8. What visual hierarchy will guide visitors?

Basically, h1 introduces me, h2 headings identify the main sections, and h3 headings identify cards. Teal buttons highlight important actions.

### 9. How will consistency be maintained across pages?

One shared stylesheet and reusable container, section, card, button, and tag classes maintain consistent colors, typography, spacing, and borders.

### 10. How will accessibility be considered (contrast, font size, readability)?

The site uses a language attribute, semantic HTML, logical headings, descriptive image alternatives, a skip link, visible focus outlines, labeled form fields, and readable controls. Status messages explain interactions, and aria-pressed identifies the selected filter. Keyboard and zoom checks are part of final testing.

### 11. Will you use icons, images, or illustrations? Why?

My photograph introduces me, and relevant project images illustrate my coursework. They give a clear image of what the user is intended to see

### 12. What portfolio websites inspired your design?

I did not base the design on a specific portfolio website. I followed the assignment requirements and chose a simple layout that I could build and understand using what I learned in class.

### Interaction / Functionality

Navigation links take visitors to sections on the page.

Project filters compare each card's single data-type value with the selected category. Matching cards remain visible, and the selected button state updates. The supplied code still needs the Spotify category and visible counter corrections below.

The contact form reads the visitor's name, email, and message. JavaScript encodes those values into a mailto draft addressed to jniet7115@gmail.com. The visitor reviews and sends the draft in their email app. A direct email link appears above the form, and the status message provides my email address if the app does not open.

The page does not store messages or confirm email delivery.

## Part 3: Interactivity

### 1. What interactive elements will your site include (navigation menus, buttons, forms)?

Section navigation links, a project call-to-action, project filter buttons, social links, and a contact form.

### 2. Will your site include a contact form? How will it work?

Yes. Visitors enter their name, email, and message. Required fields and the email input type provide browser validation. The current JavaScript checks empty strings. Adding trim() to the three input values will also reject entries that contain only spaces. Submitting requests a draft in the visitor's email app, where they review and send it.

### 3. What JavaScript features will you implement?

Variables, functions, for loops, conditions, reading HTML attributes and form values, changing project visibility, updating status text and aria-pressed, and constructing an encoded email URL.

### 4. How will users receive feedback from interactions?

The selected filter changes color. and a status message shows how many projects are visible. The browser identifies missing or invalid form entries. A message explains that visitors should review and send the draft in their email app.

### 5. How does interactivity improve the user experience?

Navigation helps visitors move to relevant sections. Filters help them focus on a project category. The form organizes their message and reply information into an email draft.
